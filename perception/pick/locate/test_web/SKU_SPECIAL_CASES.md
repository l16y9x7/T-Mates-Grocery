# SKU 定位特例记录

## 上好佳鲜虾条：上下货架同时存在

### 问题

“上好佳鲜虾条”同时存在于上下两个货架层，仅依靠 SKU 名称、包装外观或 SAM3 prompt 无法区分应该抓取哪一层。因此，该 SKU 必须先进行货架层级规则判断，再选择对应的 Qwen3 prompt。

### 当前已存储的 Prompt

当前 `qwen_prompt_mapping.json` 中存储的是 **2F（从下往上第二层货架）** 的 Prompt：

```text
找到图片中从下往上第二排货架的所有黄色虾条包装袋，输出满足条件的所有黄色虾条包装袋的bbox。返回格式：{"name": "黄色虾条包装袋", "bbox": [x1, y1, x2, y2]}
```

### 底层货架专用 Prompt

当任务目标位于最底层货架时，不能直接使用已存储的 2F Prompt，应切换为：

```text
找到图片中最底层货架的所有黄色虾条包装袋，输出满足条件的所有黄色虾条包装袋的bbox。返回格式：{"name": "黄色虾条包装袋", "bbox": [x1, y1, x2, y2]}
```

### 必需的规则判断

1. 在调用 Qwen3 之前，读取任务指定的目标货架层级。
2. 如果目标层级是 2F，使用当前已存储的 2F Prompt。
3. 如果目标层级是最底层，使用底层货架专用 Prompt。
4. 如果任务没有提供货架层级，必须标记为歧义，不能仅根据“上好佳鲜虾条”这一 SKU 自动选择上下任意一层。
5. Qwen3 返回 bbox 后，需要根据 bbox 中心点的纵坐标校验它是否位于目标货架区域；不在目标货架区域的 bbox 应被过滤。
6. SAM3 只负责在选定的 Qwen crop 中生成精细 mask，不能用于判断该商品属于上层还是底层。

### 建议的数据字段

该 SKU 的定位请求应额外携带货架层级，例如：

```json
{
  "sku_name": "上好佳鲜虾条",
  "shelf_level": "2F"
}
```

底层可使用：

```json
{
  "sku_name": "上好佳鲜虾条",
  "shelf_level": "bottom"
}
```

## 京东京造毛巾：能够识别候选区域，但无法确认

### 当前状态

当前 Qwen3 prompt 能够识别疑似“京东京造毛巾堆”的候选 bbox，但仅凭现有检测结果无法可靠确认候选区域确实是京东京造毛巾。因此，该 SKU 目前需要额外的二次确认策略，不能将 Qwen3 首次返回的 bbox 直接作为最终抓取目标。

当前 `qwen_prompt_mapping.json` 中存储的 Prompt 为：

```text
找到图片中从上往下第二层货架的京东京造毛巾堆，处于这一层的右半部分，输出满足条件的所有京东京造毛巾堆的bbox，每一堆分开。返回格式：{"name": "京东京造毛巾堆", "bbox": [x1, y1, x2, y2]}
```

### 必需的额外策略

1. 现有 Prompt 只负责生成候选毛巾堆 bbox，结果状态应标记为“待确认”。
2. 对每个候选 bbox 扩大一定范围进行二次识别，重点检查包装、标签、文字或京东京造品牌特征。
3. 可以增加商品库参考图匹配、OCR/Logo 识别或第二次独立的视觉模型确认。
4. 如果已知固定陈列位置，可以将“从上往下第二层、右半部分”作为辅助约束，但不能单独作为商品身份确认依据。
5. SAM3 的 `towel` prompt 只能细分毛巾区域，无法确认品牌，因此不能承担最终身份判断。
6. 只有候选区域通过至少一项额外身份校验后，才输出最终抓取 bbox/mask；否则返回“检测到候选，但无法确认”。

### 待确定

需要结合现场图片选择并验证最终确认方案。优先测试：

```text
候选 bbox 扩图 → 包装/标签 OCR 或品牌特征识别 → 商品库参考图相似度校验
```

在额外策略验证完成前，该 SKU 应保留为未解决特例。

## 镇江香醋、蒸鱼豉油、薄盐生抽：按固定顺序区分

### 问题

这三种商品都是外观相近的调味品瓶，视觉模型很难仅依靠瓶身外观稳定地区分。SAM3 对三者使用的也都是 `condiment bottle`，因此不能依靠 mask 类别确认具体 SKU。

### 固定顺序

当目标货架区域内检测到 **3 个或更多有效瓶子 bbox** 时，按照瓶子在画面中的水平位置从左到右排序，并按以下固定顺序标注：

1. 镇江香醋
2. 蒸鱼豉油
3. 薄盐生抽

排序依据使用 bbox 水平中心点：

```text
center_x = (x1 + x2) / 2
```

`center_x` 越小，位置越靠左。

### 规则判断

1. 先限定正确的货架区域，再检测其中所有候选调味品瓶 bbox。
2. 过滤低置信度、面积过小以及明显不属于瓶子的候选框。
3. 有效瓶子数量少于 3 时，不应用固定顺序规则，应返回“候选数量不足，无法确认”。
4. 恰好检测到 3 个有效瓶子时，按 `center_x` 从小到大排序后，依次标注为镇江香醋、蒸鱼豉油、薄盐生抽。
5. 检测到多于 3 个瓶子时，不能循环分配 SKU；应按水平位置聚成从左到右的 3 个连续商品组，再依次标注为镇江香醋、蒸鱼豉油、薄盐生抽。每组中的所有 bbox 使用同一个 SKU 名称。
6. 如果无法稳定分成 3 个水平商品组，或三个组的左右顺序与陈列规则不一致，应返回“排列异常，无法确认”，不能仅凭外观强行分类。

### 三个瓶子时的标注示例

```json
[
  {"name": "镇江香醋", "bbox": [x1, y1, x2, y2]},
  {"name": "蒸鱼豉油", "bbox": [x1, y1, x2, y2]},
  {"name": "薄盐生抽", "bbox": [x1, y1, x2, y2]}
]
```

以上数组顺序同时表示从左到右的空间顺序。

## 草原红太阳烧烤酱原味、香辣：先检测原味再排除

### 问题

“草原红太阳烧烤酱香辣”的 Qwen3 prompt 无法稳定区分香辣与原味，也会把部分原味商品检测为香辣。因此，香辣 Prompt 的检测结果不能直接作为香辣商品的最终 bbox。

相对而言，原味 Prompt 可以用于定位原味商品。识别这两个 SKU 时，应始终优先检测原味 bbox，再处理香辣候选。

### 当前 Prompt

原味 Prompt：

```text
找到图片中顶层货架的绿色烧烤酱袋子堆，输出满足条件的所有绿色烧烤酱袋子堆的bbox，每一堆分开。返回格式：{"name": "绿色烧烤酱袋子堆", "bbox": [x1, y1, x2, y2]}
```

香辣 Prompt：

```text
找到图片中顶层货架的红色烧烤酱袋子堆，输出满足条件的所有红色烧烤酱袋子堆的bbox，每一堆分开。返回格式：{"name": "红色烧烤酱袋子堆", "bbox": [x1, y1, x2, y2]}
```

### 识别顺序

1. 无论当前请求的是原味还是香辣，都先运行原味 Qwen3 Prompt，记录所有原味 bbox。
2. 请求原味时，优先使用原味 Prompt 的检测结果。
3. 请求香辣时，再运行香辣 Prompt，得到包含香辣和误检原味的候选 bbox。
4. 将香辣候选与已记录的原味 bbox 进行空间匹配；与原味 bbox 重合的候选从香辣结果中排除。
5. 排除原味后的剩余候选，才可以作为香辣 bbox。
6. 如果排除后没有候选，或者候选与原味 bbox 无法明确分开，应返回“无法确认香辣”，不能直接采用香辣 Prompt 的原始结果。

### bbox 排除规则

可以使用 IoU 和中心点包含关系匹配同一个商品堆：

```text
same_candidate = IoU(spicy_bbox, original_bbox) >= 0.5
                 or center(spicy_bbox) 位于 original_bbox 内
                 or center(original_bbox) 位于 spicy_bbox 内
```

满足任一条件时，将该香辣候选视为原味误检并排除。阈值需要结合现场图片验证；如果 Qwen3 两次输出的框大小差异较大，应优先参考中心点包含关系。

### 核心原则

```text
香辣最终 bbox = 香辣 Prompt 候选 bbox - 原味 Prompt 已确认 bbox
```

SAM3 对两者都使用 `condiment package`，只能生成精细 mask，不能替代上述口味区分规则。

## 可口可乐罐装：排数判断依赖 SAM3

### 问题

Qwen3-VL 能用于定位顶层货架上的可口可乐大致区域，但无法可靠识别其中具体有几排。因此，不能信任 Qwen3-VL 返回的排数，也不能仅根据它生成的“可口可乐排”bbox 决定最终分排结果。

当前 Qwen3 Prompt 为：

```text
找到图中顶层货架上所有可口可乐排的bbox，每一排分开。最终返回格式：{"name": "可口可乐排", "bbox": [x1, y1, x2, y2]}
```

### 处理策略

1. 使用 Qwen3-VL 只定位可口可乐所在的粗略区域或 crop，不采用它判断的排数。
2. 在 Qwen crop 内使用 SAM3 Prompt `beverage can`，分割每一个可见罐装实例。
3. 根据每个 SAM3 实例 bbox 的纵向中心点进行聚类，以确定罐子属于哪一排：

```text
center_y = (y1 + y2) / 2
```

4. `center_y` 接近的罐子归为同一排；最终排数等于有效纵向分组数量。
5. 每一排的 bbox 使用该组所有罐装实例 bbox 的外接矩形：

```text
row_bbox = [min(x1), min(y1), max(x2), max(y2)]
```

6. 输出排的顺序按 `center_y` 从小到大排列，即从画面上方到下方。
7. 如果 SAM3 实例存在明显漏检、粘连或纵向分组不稳定，应返回“排数无法确认”，不能回退使用 Qwen3-VL 猜测的排数。

### 核心原则

```text
Qwen3-VL：只负责可口可乐区域粗定位
SAM3：负责单罐实例分割、数量统计和排数判断
```

该 SKU 的最终排 bbox 和排数必须以 SAM3 实例结果为依据。

“小青柠汁饮料”与“可口可乐罐装”采用相同策略：Qwen3-VL 只能用于定位商品的大致区域，无法可靠确认瓶子的具体数量和排数；最终结果必须依赖 SAM3 的单瓶实例分割。

当前 Qwen3 Prompt 为：

```text
找到图片中从上往下第二层货架的黄色小青柠汁，输出满足条件的所有黄色小青柠汁的bbox。返回格式：{"name": "黄色小青柠汁", "bbox": [x1, y1, x2, y2]}
```

处理规则：

1. 使用 Qwen3-VL 定位从上往下第二层货架中的黄色小青柠汁区域，并生成用于 SAM3 的 crop。

Qwen3-VL：只负责小青柠汁区域粗定位
SAM3：负责单瓶分割、数量统计和排数判断

## 美年达瓶装：Qwen3 粗定位后由 SAM3 选出前两个

### 当前 Prompt

```text
找到图片中从上往下第二层货架的美年达饮料堆，输出满足条件的所有美年达饮料堆的bbox，每一堆分开。返回格式：{"name": "美年达饮料堆", "bbox": [x1, y1, x2, y2]}
```

### 处理策略

1. 先运行 Qwen3-VL，识别美年达饮料堆的 bbox。
2. 将 Qwen bbox 适当向外扩张生成 crop，避免裁掉边缘瓶身。
3. 在 crop 内使用 SAM3 Prompt `beverage bottle`，分割所有可见的美年达瓶实例。
4. 过滤低置信度、面积过小和高度重叠的重复实例。
5. 根据 `FRONT_MASK_HEURISTIC.md` 中的 mask 面积、mask 点密度和 bbox 大小规则，对 SAM3 实例进行前后排序。
6. 选择排序最靠前的两个 SAM3 实例，输出它们各自的 mask 和映射回原图的 bbox。
7. 如果有效实例不足两个，只返回实际检测到的实例数量，并标记“前方实例不足 2 个”，不能复制同一个实例补足两个。
8. 如果第二名与后续实例的前后评分非常接近，标记为“第二个目标不确定”，保留候选结果供后续策略判断。

### 核心流程

```text
Qwen3 美年达饮料堆 bbox
    → bbox 扩图
    → SAM3 beverage bottle 实例分割
    → 前后关系评分
    → 选出最前方两个实例
```

## 脉动四种口味：共用 Qwen3 Prompt，结合 SAM3 与计数

适用 SKU：

- 脉动观梅止渴饮
- 脉动芒果口味
- 脉动菠萝口味
- 脉动猫薄荷瓶

### 当前状态

四个 SKU 当前保存了完全相同的 Qwen3 Prompt：

```text
找到图片中从上往下第二层货架的脉动水瓶堆，输出满足条件的所有脉动水瓶堆的bbox，每一堆分开。返回格式：{"name": "脉动水瓶堆", "bbox": [x1, y1, x2, y2]}
```

该 Prompt 只能识别脉动水瓶堆，不能单独区分四种口味，也不能直接确定应该选择多少个瓶子。四个 SKU 不应重复运行四次相同的 Qwen3 检测；应复用一次粗定位结果，再结合 SAM3 实例分割和任务计数处理。

### 处理策略

1. 使用共用 Qwen3 Prompt 获取脉动水瓶堆 bbox，并扩张生成 crop。
2. 在 crop 内使用 SAM3 Prompt `beverage bottle`，分割所有可见脉动瓶实例。
3. 过滤低置信度、面积过小以及高度重合的重复 mask，得到有效实例列表。
4. `available_count` 使用过滤后的 SAM3 实例数量，而不是 Qwen3 返回的 bbox 数量：

```text
available_count = 有效 SAM3 bottle 实例数量
```

5. 读取任务所需数量 `required_count`，根据 `FRONT_MASK_HEURISTIC.md` 的前后评分对实例排序，并选取最前方的指定数量：

```text
selected_count = min(required_count, available_count)
```

6. 当 `available_count < required_count` 时，返回实际实例并标记“可用数量不足”，不能重复使用同一个 mask 补足数量。
7. 如果任务没有提供 `required_count`，必须先获取或明确默认数量，不能仅凭 Qwen3 bbox 猜测需要选择几个实例。

### 口味确认限制

Qwen3 共用 Prompt 和 SAM3 的 `beverage bottle` 都不能确认具体口味。SAM3 与计数只能解决实例数量和抓取顺序，不能独立完成四种 SKU 的身份区分。

如果四种口味在货架上有固定位置，需要额外记录位置与 SKU 的映射；如果位置不固定，则需要包装颜色、标签 OCR、参考图匹配或其他二次分类策略。未完成口味确认时，应返回“已检测脉动实例，但口味无法确认”。

### 核心流程

```text
一次共用 Qwen3 粗定位
    → SAM3 单瓶实例分割
    → 有效实例计数
    → 按前后关系排序
    → 根据 required_count 选择实例
    → 额外策略确认具体口味
```

## 饮料类 SKU 统一策略：Qwen3 完整框选，SAM3 选择最前排

### 适用范围

该规则适用于全部饮料类型 SKU，包括瓶装、罐装以及其他需要从一组陈列商品中选择前排实例的饮料。当前 SAM3 Prompt 为 `beverage bottle` 或 `beverage can` 的商品默认应用此规则；其他饮料包装类型也按同样流程处理，只需替换对应的 SAM3 Prompt。

### 统一处理流程

1. 使用该 SKU 对应的 Qwen3 Prompt 检测饮料陈列区域。
2. Qwen3 返回的 bbox 必须覆盖完整的目标商品堆或陈列区域，不能只框住单瓶、局部瓶身或其中一排。
3. 检查 bbox 是否贴边截断商品；必要时在不跨入相邻 SKU 区域的前提下向外扩张，生成完整 crop。
4. 在完整 Qwen crop 内运行对应的 SAM3 Prompt，分割所有可见饮料实例。
5. 过滤低置信度、面积过小、残缺严重以及高度重叠的重复 mask。
6. 使用 `FRONT_MASK_HEURISTIC.md` 中记录的 mask 面积、mask 点密度和 bbox 大小计算前后关系。
7. 将尺寸与前后评分相近的实例归为同一排，选择评分最高的实例组作为最前排。
8. 最终只输出最前排实例的 mask，以及映射回原图的单体 bbox；后排实例保留为候选信息，但不作为当前抓取目标。

### 前排选择规则

- 如果最大 mask 面积至少是第二大 mask 的 2 倍，直接优先选择最大 mask；是否还存在同一前排实例，需要结合其余实例的尺寸分组判断。
- 一般情况下，对 `front_score` 或归一化 mask 面积进行分组，选择得分最高的一组作为最前排，而不是只选择单个最大实例。
- 同一前排中的实例应具有相近的视觉尺寸和前后评分；具体分组阈值需要使用现场数据标定。
- SAM3 明显漏检、mask 粘连或前后分组不稳定时，应返回“最前排无法确认”，不能直接使用 Qwen3 bbox 代替单体结果。

### 与数量规则的关系

饮料统一策略先得到“最前排实例集合”，再应用具体 SKU 的数量要求：

```text
Qwen3 完整商品区域 bbox
    → SAM3 分割全部饮料实例
    → 筛选最前排实例集合
    → 按具体 SKU 的 required_count 选择实例
```

- 没有数量要求时，返回最前排的全部有效实例。
- 美年达瓶装在最前排实例中选择前两个。
- 脉动四种口味在最前排实例中结合 `required_count` 选择。
- 可口可乐罐装、小青柠汁饮料的数量与排数以 SAM3 实例及其分组结果为准。

### 核心原则

```text
Qwen3：检测完整饮料商品区域 bbox
SAM3：分割单体、判断前后排、输出最前排实例
```
