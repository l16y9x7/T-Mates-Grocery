## 当前重点样本

优先覆盖这些情况：

1. 单商品、清晰、无口味。
2. 多商品。
3. 相同或相似商品多行，需要确认每条商品明细都保留为独立输出。
4. 商品名跨行。
5. 名字非常相似的商品。
6. 口味词相似，例如番茄味、番茄酱味、墨西哥鸡汁番茄味。

## 2026-07-31：完整商品名 + 规格字段实验

本轮将业务输出从 `name/flavor/specification/count/source_text` 收束为：

```json
[
  {"name": "完整票面商品名称", "specification": "票面规格"}
]
```

改动原因：

- 旧版本让模型额外拆分 `flavor`，在“青柠味/柠檬味”“墨西哥鸡汁番茄味”“香辣牛肉面”等相似或跨行文本上更容易出错。
- 当前比赛阶段更关心商品能否唯一对应库存 SKU，因此完整商品名比拆分口味更直接。
- 数量当前固定视为 1，`count` 暂不输出；`source_text` 也暂不输出，避免后续逻辑依赖模型生成的中间文本。
