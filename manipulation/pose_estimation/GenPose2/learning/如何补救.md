# 深度数据大量丢失：原因与补救（不改代码）

本文基于案例 `20260623_092101_182cc699` 的排查结论，说明 **为什么会出现大量 depth=0**，以及 **在不改 GenPose2 / HTTP 服务代码的前提下** 可以采取的补救措施。

相关文档：[案例分析 1](./案例分析1.md)

---

## 1. 这次具体发生了什么

| 区域 | 有效深度占比 | 说明 |
|------|-------------|------|
| 线轴大致 ROI（黄框，x:200–450, y:80–300） | ~**40%** | 深度传感器 **能测到** 线轴附近 |
| **Mask 内**（红框，33×196 px 窄条） | 仅 **7.8%** | **92.2%** 为 depth=0 |

结论：**不是整帧深度都坏了**，而是 **mask 落在深度最不可靠的区域**（线轴边缘、支架镂空、半透明区域）。

Mask 仅 33×196 px 竖条，GenPose2 需从 mask 内采样约 1024 点建点云，实际只有 **415** 个有效点，位姿可信度低（PEM z 与 mask 内深度中位数相差约 **127 mm**）。

---

## 2. 为什么会有大量深度丢失

### 2.1 材质导致（最主要）

场景：**白色半透明塑料线轴 + 镀铬金属线架**。

结构光 / ToF / 双目深度（RealSense 等）在这些材质上容易失败：

| 材质 | 问题 |
|------|------|
| **半透明塑料** | 红外穿透或散射，深度落在物体前后不确定位置，或直接无效 |
| **金属细线 / 高反光** | 信号被反射走，出现 flying pixels 或 depth=0 |
| **镂空支架** | 看到的是背景深度，物体表面无稳定回波 |

这是 **传感器物理限制**，不是单靠后端算法能「算回来」的。

### 2.2 Mask 与有效深度不对齐

ROI 内约 40% 像素有有效深度，但 mask 所在窄条 **92% 为空**。  
推理用的是 **mask 内的点**，不是 ROI 内「看起来还行」的区域。

### 2.3 全图深度本身较稀疏

全图约 55% 像素 depth=0，对室内 RGB-D 不算极端；但若 **物体表面恰好落在无效区**，6D 推理就会失败。

### 2.4 软件侧进一步丢弃（次要）

GenPose2 `InferDataset` 还会：

- 深度 **> 4 m** → 置 0  
- 仅在 mask 内取点云

本案例主要问题是 **原始 depth 就是 0**，不是 `depth_scale` 或 4 m 阈值导致（内参与单位已验证正常）。

## 3. 不改代码的补救办法

按 **投入从小到大** 排列。

### 3.1 改 Mask（最快、最有效）

1. **把 mask 画/分割到线轴盘面主体**，不要 33 px 竖条边缘。  
2. **避开** 金属线、镂空、强反光边。  
3. 原则：mask 应主要落在 RGB 上可见、且 **depth > 0 稳定** 的区域。  
4. 上传前自检：

```
mask_valid_depth_ratio = (mask 内 depth>0 像素数) / (mask 前景像素数)
```

| ratio | 建议 |
|-------|------|
| > 0.5 | 可正常推理 |
| 0.2 ~ 0.5 | 谨慎使用，检查 mask/深度对齐 |
| < 0.2 | 先修正 mask 或采集，不建议直接推理 |

本案例 ratio ≈ **7.8%**，属于最后一档。

**参考可视化**：`learning/outputs/案例分析1/` 中 `depth_colormap.png`（红框=目标）、`mask_depth_validity.png`（绿=有效、红=无效）。

---

### 3.2 改采集角度与距离

1. **略抬高或侧移相机**，减少透过线轴看到后面支架。  
2. **拉近** 线轴（在量程内），提高有效像素密度。  
3. 避免深度相机 **正对着** 大面积半透明面；略侧视往往更好。  
4. 减少背景里 **高反光金属** 进入 mask。

---

### 3.3 改光照与环境

1. 避免强点光源直射线轴/支架（加剧反光和半透明问题）。  
2. 使用 **均匀漫射光**，RGB 与深度通常更稳。  
3. 背景尽量 **哑光、低反光**（白墙相对尚可）。

---

### 3.4 深度相机端设置（RealSense 等 SDK）

在 **采集端** 调整，无需改 GenPose2 代码：

| 手段 | 作用 |
|------|------|
| Spatial / Temporal Filter | 填小洞、多帧时间融合 |
| Hole Filling | 插值小范围 depth=0 |
| 分辨率 / Decimation | 有时略降分辨率反而更稳 |
| Exposure / Laser Power | 半透明物体可实测微调 |
| **多帧平均** | 静止场景连拍 5–10 帧取中值或平均 |

注意：对 **整片透明/镂空** 的大空洞，滤波无法恢复，只能改善 **小洞**。

---

### 3.5 换深度源或融合（成本较高）

若业务允许：

1. **工业结构光 / 线激光**（强反光场景常需偏振或临时哑光处理）。  
2. **多视角融合**：换角度再拍，对齐到同一 mask（工程量大）。  
3. 深度补全网络（属于算法/后处理层，需单独开发，此处不展开）。

---

### 3.6 改流程：优化 mask 来源

当前模式为 **上传 mask + 跳过分割**（`seg_backend=provided`）。可尝试：

1. 在 RGB 上用 **SAM / 手动** 得到 **完整线轴 mask**（非细条）。  
2. 或服务端用 **SAM3 文本提示** 分割，再与 depth 有效性交叉检查。  
3. 无论来源，**分割 mask ≠ 一定适合推理**，必须看 mask 内有效深度占比。

---

## 4. 如何验证补救是否有效

每次采集 / 每次 `/infer` 前，建议检查三项：

| 检查项 | 合格参考 |
|--------|----------|
| Mask 内有效深度占比 | **> 50%** |
| Mask 内有效深度中位数 | 与物体实际距离接近（本场景约 0.4–0.8 m） |
| PEM 的 `t[2]`（z, mm）与 mask 内深度中位数 | 相差 **< 50 mm**（本案例约 127 mm，不可信） |

推理成功后，接口返回的 `depth_colormap_path` 可直接查看：**目标红框内是否有彩色深度**（0.3–1.0 m 色图）；若框内多为深灰，说明仍未补救到位。

## 5. 本案例总结

| 项目 | 结论 |
|------|------|
| 内参 K | ✅ 正常 |
| depth 单位（depth_scale） | ✅ 正常（PNG 自动 ×0.001） |
| 全图 depth | ⚠️ 尚可但偏稀疏 |
| Mask | ❌ 过窄，且落在 depth 空洞区 |
| **丢失主因** | 半透明线轴 + 金属架 + **mask 位置不当** |
| **优先补救** | **扩大/移动 mask 到盘面有效深度区域** |
| **其次** | 调相机角度、RealSense 滤波、多帧融合 |

**本质**：不是「深度文件损坏」，而是 **这类材质下 depth 本来就不完整**；必须把 mask 与 **depth 可靠区域** 对齐，GenPose2 才有足够几何约束。
